# 足球（Party Game 第二個遊戲）規劃

參考：[Alpaca Ball: Allstars](https://www.nintendo.com/games/detail/alpaca-ball-allstars-switch/)
（最多 8 人的物理足球派對遊戲；用頭和長脖子頂球，有跳躍、衝刺、蓄力射門，場上會隨機出現道具，球還可能變成排球、冰球、骰子）

> 狀態：**規劃中**，大廳已放「足球」卡片（`GAMES` 裡 `enabled: false`）。下面標「待決定」的是需要你拍板的地方。

---

## 1. 核心玩法（一句話）
**朋友的大頭用脖子頂球，把球頂進對方球門；隊伍對戰，3 分鐘內進球多的贏。**
我們的角色本來就是「大頭」，「頭槌踢球」比參考作品更貼題。

## 2. 規則（MVP）
| 項目 | 設計 |
|---|---|
| 視角 | 側視 2D，一個固定的球場畫面（和跑步一樣整場都在 1280×720 畫布內，不捲動） |
| 隊伍 | 紅隊 / 藍隊，依加入順序輪流分配、人數平衡；**待決定：也想要「每人各自為戰」嗎？** |
| 人數 | 2～8 人（和參考作品一樣）。超過 8 人的處理見第 7 節 |
| 時間 | 一場 3 分鐘（`MATCH_SECONDS`），時間到分數高者勝；平手 → 金球（下一球定勝負） |
| 進球後 | 慶祝 2 秒 → 雙方回到起始位置 → 3、2、1 開球 |
| 結算 | 勝負 + 每人進球數（MVP）；顯示在結算面板，按「再來一場」或「回遊戲大廳」 |
| 玩家顏色 | 沿用選好的衣服顏色；隊伍用腳下的**隊色環／頭上的隊色小旗**區分（不強制換衣服，因為顏色是每人獨一無二的） |

## 3. 手機操作（重點：不是「連打」，是「按住」）
跑步用「單次點擊」；足球需要**持續輸入**，所以手機端要換一套按鈕：

```
┌───────────────────────┐
│   （上方：隊伍／比數）   │
│                       │
│  ┌────┐┌────┐   ┌───┐ │
│  │ ◀  ││ ▶  │   │跳 │ │   左手拇指：左右移動
│  └────┘└────┘   └───┘ │   右手拇指：跳 / 衝刺 / 頭槌
│                ┌───┐┌───┐│
│                │衝刺││頭槌││
│                └───┘└───┘│
└───────────────────────┘
```
- **◀ ▶**：按住移動（也可以改成虛擬搖桿，待決定；按鈕比較不會誤觸、也不需要額外的觸控處理）。
- **跳**：點一下跳。
- **衝刺**：點一下向面對方向衝一小段，有冷卻（約 1.5 秒）。
- **頭槌（伸脖子）**：按住 = 脖子慢慢伸長蓄力，放開 = 脖子彈出去把球打飛；蓄越久越遠越快（參考作品的「蓄力射門」）。
- 多點觸控：移動和動作是兩根不同手指，pointer events 本來就支援（跑步已經用同樣做法）。

### 網路協定
跑步送的是 `tap` 事件；足球改送**按鍵狀態**，只在「變化時」送，不是每格都送：
```js
socket.emit('input', { l: true, r: false, jump: false, dash: false, neck: true })
```
- server 只轉送（維持「server 不含遊戲規則」的原則），host 收到後存成「這個玩家目前按著什麼」。
- 手機分頁切走、斷線、放開失敗時，host 要有**保險**：超過 N 秒沒收到輸入、或收到 `player:left`，就把這個玩家的按鍵全部清成放開（不然會卡在一直往右跑）。

## 4. 技術架構
**host 是唯一的物理運算者**（和現在一樣，所有遊戲邏輯都在 host.js）。
```
手機 ──input──▶ server（只轉送）──▶ host（固定 60Hz 模擬）──▶ 畫面
                                      │
                                      └─ 只把「該手機需要知道的」狀態傳回去（隊伍、比數、倒數）
```
- 物理：先用 **Phaser Arcade Physics**（圓形碰撞體，夠用、效能好）。球要更「Q 彈」或想要旋轉時再換 Matter。
- 一台電視（host 瀏覽器）要算：8 個玩家 + 1 顆球 + 道具，完全沒有效能問題。
- **延遲**：手機 → server → host 約 50～150ms（Render 雲端）。玩家看的是大螢幕，不是手機，所以不做預測／回滾；host 權威、直接套用輸入即可。區網內延遲更低。
- 程式拆分（足球做進去的時候一併做）：
  ```
  public/host.js          ← 大廳、玩家、socket（不動）
  public/games/race.js    ← 現在 host.js 裡的跑步邏輯搬過去
  public/games/soccer.js  ← 新增
  ```
  每個遊戲實作同一組介面：`{ id, start(ctx), stop(), onInput(playerId, input), statusOf(player) }`，大廳的 `GAMES` 清單只負責呼叫 `start()`。
- `game:state` 已經帶 `game` 欄位，手機端可以依遊戲換不同的操作畫面（跑步＝左右兩顆；足球＝上面那組）。

## 5. 角色呈現
- **身體**：程式畫的小身體（沿用跑步的繪製方式，這次要加「站著」「跳」「衝刺」幾個姿勢）。
- **脖子**：身體和頭之間畫一條會伸縮的線（粗圓角線），長度 = 蓄力量；**頭 = 玩家的 `head` 圖**，頭是真正的碰撞體。
- **頭槌動畫**：脖子由短變長（蓄力）→ 放開後頭往前撞出去再彈回。
- 隊色環：腳下一個橢圓。進球時：頭轉一圈 + 彩帶（跑步已有）。

## 6. 道具（第二階段，不進 MVP）
參考作品的亮點，但放在能玩之後再加：
| 道具 | 效果 |
|---|---|
| 巨人 | 自己變大 |
| 長脖子 | 脖子最長距離變 2 倍 |
| 磁鐵／念力 | 一段時間把球吸向自己 |
| 冰地 / 彈跳 | 場地摩擦力改變 |
| 換球 | 球變成排球／冰球／方塊骰（反彈特性不同） |
隨機從天上掉下來、碰到就生效、約 10 秒結束。

## 7. 人數超過 8 人
和跑步的「分組輪流」同樣想法，**待決定**其中一種：
1. **輪替**：場上 8 人，其他人當觀眾；每場結束輸的那隊換下去（贏家留場）。
2. **分場**：10 人 → 5v5 打一場，其他人等下一場，最後比總進球。
3. **限制人數**：足球最多 8 人，多的人先等。

## 9. 風險與對策
| 風險 | 對策 |
|---|---|
| 手機延遲讓操作黏黏的 | 輸入只送「變化」；加速度/摩擦調得寬鬆一點；實機在 Render 上測，不只區網 |
| 輸入卡住（斷線、切分頁） | 輸入逾時自動清除；`visibilitychange` 時手機主動送「全放開」 |
| 球卡在角落/玩家夾球 | 球加上最大速度、角落給一個把球推出去的緩衝；球靜止太久自動重發球 |
| 8 人一起碰撞很亂（這也是樂趣） | 玩家之間只擠不撞飛，或只讓「頭」和球碰撞 |
| 繁體中文字型、手機尺寸 | 沿用目前做法；按鈕尺寸 ≥ 72px |

## 10. 需要你決定的事
1. **隊伍制 vs 各自為戰**？（建議：隊伍制，最像足球）
2. **操作用按鈕 vs 虛擬搖桿**？（建議：先用 ◀ ▶ 按鈕）
3. **超過 8 人**怎麼辦？（建議：輸的隊輪替下場）
4. **球門與場地**要不要做主題（例如操場 / 神社，和你的 Street Fighter 風格圖一致）？
5. 角色身體要不要你也做圖？（現在是程式畫的火柴人；足球需要新增站姿/跳躍/頭槌姿勢）

# 足球（Party Game 第二個遊戲）規劃

參考：[Alpaca Ball: Allstars](https://www.nintendo.com/games/detail/alpaca-ball-allstars-switch/)
（最多 8 人的物理足球派對遊戲；用頭和長脖子頂球，有跳躍、衝刺、蓄力射門，場上會隨機出現道具，球還可能變成排球、冰球、骰子）

> 狀態：**M4 已完成**（紅藍分隊、進球計分、3 分鐘、金球加時、結算、頭槌蓄力、衝刺、脖子伸縮、10 人壓力測試、斷線／重連處理；還沒有道具）。程式在 `public/games/soccer.js`。
>
> **已決定**：① 手機用**虛擬搖桿**（上下左右都能移動）；② 角色**沿用跑步的做法**（玩家的大頭 + 程式畫的跑步身體）；③ 隊伍制 4v4／5v5。標「待決定」的是還需要你拍板的地方。

---

## 1. 核心玩法（一句話）
**朋友的大頭用脖子頂球，把球頂進對方球門；隊伍對戰，3 分鐘內進球多的贏。**
我們的角色本來就是「大頭」，「頭槌踢球」比參考作品更貼題。

## 2. 規則（MVP）
| 項目 | 設計 |
|---|---|
| 視角 | **俯視 2D**（因為要上下左右都能移動），一個固定的球場畫面，整場都在 1280×720 畫布內，不捲動。角色用跑步的側面小人站在場上，越下面的越晚畫（遮擋順序） |
| 隊伍 | 紅隊 / 藍隊，依加入順序輪流分配、人數平衡；**待決定：也想要「每人各自為戰」嗎？** |
| 人數 | 2～10 人（4v4 或 5v5，奇數人時一隊多一人）。超過 10 人的處理見第 7 節 |
| 時間 | 一場 3 分鐘（`MATCH_SECONDS`），時間到分數高者勝；平手 → 金球（下一球定勝負） |
| 進球後 | 慶祝 2 秒 → 雙方回到起始位置 → 3、2、1 開球 |
| 結算 | 勝負 + 每人進球數（MVP）；顯示在結算面板，按「再來一場」或「回遊戲大廳」 |
| 玩家顏色 | 沿用選好的衣服顏色；隊伍用腳下的**隊色環／頭上的隊色小旗**區分（不強制換衣服，因為顏色是每人獨一無二的） |

## 3. 手機操作（重點：不是「連打」，是「按住」）
跑步用「單次點擊」；足球需要**持續輸入**，所以手機端要換一套：

```
┌───────────────────────┐
│   （上方：隊伍／比數）   │
│                       │
│                       │
│   ╭───╮               │   左手拇指：虛擬搖桿（移動）
│  (  ●  )    ┌─────┐   │   右手拇指：
│   ╰───╯     │ 頭槌 │   │     頭槌（按住蓄力、放開撞出去）
│  搖桿        └─────┘   │     衝刺
│             ┌─────┐   │
│             │ 衝刺 │   │
│             └─────┘   │
└───────────────────────┘
```
- **虛擬搖桿（浮動式）**：拇指按在左半邊畫面的哪裡，搖桿就出現在哪裡；往任何方向拖就往那個方向走，拖得越遠越快。放開就停。
  - 死區約 15%，避免手指微抖。
  - 用 pointer events + `setPointerCapture`，手指拖出搖桿範圍也不會斷。
  - 右半邊兩顆按鈕是另一根手指，pointer events 本來就支援同時多點觸控（跑步已經在用）。
- **衝刺**：點一下朝目前方向衝一小段，有冷卻（約 1.5 秒）。
- **頭槌（伸脖子）**：按住 = 脖子慢慢伸長蓄力，放開 = 頭朝**目前面向的方向**撞出去再彈回；蓄越久越遠越快（參考作品的「蓄力射門」）。
- 不做「跳」：俯視沒有高度，跳沒有意義，空出來的按鍵留給之後的道具。

### 網路協定
跑步送的是 `tap` 事件；足球改送**輸入狀態**，只在「變化時」送：
```js
socket.emit('input', { mx: 0.62, my: -0.31, dash: false, neck: true })   // mx, my 範圍 -1~1，取到小數 2 位
```
- 搖桿拖動時最多每 50ms（20Hz）送一次，其餘只在按鈕按下／放開、搖桿放開（`mx=0,my=0`）時送。
- server 只轉送（維持「server 不含遊戲規則」的原則），host 收到後存成「這個玩家目前的輸入」，每個物理 tick 讀取。
- 手機分頁切走、斷線、放開失敗時，host 要有**保險**：超過 500ms 沒收到搖桿更新就慢慢減速停下；收到 `player:left` 就清空；手機在 `visibilitychange` 時主動送「全放開」。

## 4. 技術架構
**host 是唯一的物理運算者**（和現在一樣，所有遊戲邏輯都在 host.js）。
```
手機 ──input──▶ server（只轉送）──▶ host（固定 60Hz 模擬）──▶ 畫面
                                      │
                                      └─ 只把「該手機需要知道的」狀態傳回去（隊伍、比數、倒數）
```
- 物理：先用 **Phaser Arcade Physics**（圓形碰撞體，夠用、效能好）。球要更「Q 彈」或想要旋轉時再換 Matter。
- 一台電視（host 瀏覽器）要算：8 個玩家 + 1 顆球 + 道具，完全沒有效能問題。
- **延遲**：手機 → server → host 約 50～150ms（Render 雲端）。玩家看的是大螢幕，不是手機，所以不做預測／回滾；host 權威、直接套用輸入即可。區網內延遲更低。
- 程式拆分（足球做進去的時候一併做）：
  ```
  public/host.js          ← 大廳、玩家、socket（Hub）
  public/char-render.js   ← 共用：大頭與跑步身體（足球直接重用）
  public/games/race.js    ← 跑步（M0 已完成）
  public/games/soccer.js  ← 新增
  ```
  每個遊戲實作同一組介面：`{ id, start(ctx), stop(), onInput(playerId, input), statusOf(player) }`，大廳的 `GAMES` 清單只負責呼叫 `start()`。
- `game:state` 已經帶 `game` 欄位，手機端可以依遊戲換不同的操作畫面（跑步＝左右兩顆；足球＝上面那組）。

## 5. 角色呈現（先沿用跑步的做法）
- **直接重用跑步的角色**：`ensureBody()` 的 6 格跑步動畫 + 玩家的 `head` 圖 + 衣服顏色，不需要新美術。
  - 往右跑就正常播放，往左跑把角色水平翻轉（`scaleX = -1`）；往上下跑也用同一組動畫（俯視下看起來就是在跑）。
  - 速度越快動畫播越快、停下來站著（跑步已有這段邏輯）。
  - 名字顯示在頭的左邊 → 足球改成頭上方（場上人多，貼在頭上比較好認）。
- **MVP 的頭槌**：先不做脖子伸縮，按「頭槌」時頭往前一撞（頭沿著面向方向位移 + 變大一點），這段時間內頭和球碰撞會給球更大的力。
- **之後再加**（M3）：身體和頭之間畫一條會伸縮的粗線當脖子，長度 = 蓄力量。
- 隊色環：腳下一個橢圓。進球時：頭轉一圈 + 彩帶（跑步已有）。
- 新增美術需求：**無**（你之後想換成姿勢更多的身體圖時再說）。

## 6. 道具（第二階段，不進 MVP）
參考作品的亮點，但放在能玩之後再加：
| 道具 | 效果 |
|---|---|
| 巨人 | 自己變大 |
| 長脖子 | 脖子最長距離變 2 倍 |
| 磁鐵／念力 | 一段時間把球吸向自己 |
| 冰地 / 彈跳 | 場地摩擦力改變 |
| 換球 | 球變成排球／冰球／方塊骰（反彈特性不同） |
隨機從天上掉下來、碰到就生效、約 10 秒結束。

## 7. 人數超過 10 人
和跑步的「分組輪流」同樣想法，**待決定**其中一種：
1. **輪替**：場上 10 人，其他人當觀眾；每場結束輸的那隊換下去（贏家留場）。
2. **分場**：例如 14 人 → 7v7 不行，改成先 5v5 再 4v5，最後比總進球。
3. **限制人數**：足球最多 10 人，多的人先等。

## 9. 風險與對策
| 風險 | 對策 |
|---|---|
| 手機延遲讓操作黏黏的 | 輸入只送「變化」；加速度/摩擦調得寬鬆一點；實機在 Render 上測，不只區網 |
| 輸入卡住（斷線、切分頁） | 輸入逾時自動清除；`visibilitychange` 時手機主動送「全放開」 |
| 球卡在角落/玩家夾球 | 球加上最大速度、角落給一個把球推出去的緩衝；球靜止太久自動重發球 |
| 10 人擠在同一個場地 | 場地用滿 1280×720；玩家之間只輕微擠開、不彈飛；只有「頭」和球碰撞 |
| 搖桿在手機上誤觸 / 拇指遮住畫面 | 浮動式搖桿、手機只顯示簡單的按鈕與比數，真正的畫面在大螢幕 |
| 繁體中文字型、手機尺寸 | 沿用目前做法；按鈕尺寸 ≥ 72px |

# 陀螺大戰（Party Game 第三個遊戲）規劃

> 狀態：**S1 已完成**（碗型平台、手機陀螺儀操控、準備階段、搖桿備案）。程式在 `public/games/spinner.js` 與 `public/controller.js`。**陀螺儀只在邏輯上驗證過（用程式模擬傾斜事件）；iPhone 授權視窗、感測器準不準、實際手感都必須用真的手機（Render 的 https 網址）測。**標「需實機驗證」的是我無法在這個環境測的地方。
>
> **S1 追加的決定**：⑤ **平台改成碗型（中間下凹）**：碗的拉力與離中心的距離成正比，往中心衝會加速、往外圍衝會減速，比較不會自己衝出去；縮圈時碗的形狀不變，邊緣越來越靠近中心、拉力越來越小，所以越縮越容易掉出去。
>
> **已決定（S0）**：① 個人混戰；② 共兩回合——**第 1 回合計時賽**（被撞出平台 5 秒後復活，計算擊殺數）、**第 2 回合淘汰賽**（不復活、平台縮小，玩到剩最後 3 位）；③ 先不做轉速與衝撞，當成圓盤互撞；④ 圓盤中間放角色大頭。
>
> **最終名次的算法**（我自己定的，要改告訴我）：第 2 回合留下來的人排前面，彼此依第 1 回合擊殺數排序（同分看第 2 回合擊殺）；其餘人依淘汰順序，越晚淘汰名次越高。人數 4 人以上留最後 3 位；3 人以下打到剩 1 位；1 人只打第 1 回合。

## 1. 核心玩法（一句話）
**每個人的大頭是一顆旋轉的陀螺，用手機的陀螺儀（傾斜手機）操控移動，互相撞擊，把別人撞出平台；最後留在台上的人獲勝。**

## 2. 規則（MVP）
| 項目 | 設計 |
|---|---|
| 視角 | 俯視 2D，一座圓形平台在畫面正中央（平台直徑約 560，畫布 1280×720，兩旁留空間放計分板） |
| 人數 | 2～10 人，**混戰**（各自為戰）。超過 10 人的處理沿用足球的做法（待決定） |
| 一回合 | 最後一個還在台上的人贏；掉出平台就淘汰。約 30～90 秒 |
| 賽制 | 共 3 回合；每回合依「存活順序」計分（最後留下 = 人數分，第一個淘汰 = 1 分），3 回合總分最高者獲勝（待決定：也可以改成「先贏 2 回合」） |
| 縮圈 | 回合開始 25 秒後平台開始慢慢縮小（最小到約 45%），避免有人一直躲在邊緣不碰人 |
| 掉出平台 | 陀螺中心超過平台邊緣 → 縮小旋轉掉下去（落水特效）→ 淘汰，之後當觀眾，手機顯示「你被淘汰了，看別人打」 |
| 勝負外的小統計 | 每回合顯示「撞出最多人」的玩家（擊殺數：最後一個碰到你的人算他撞出去的，3 秒內有效） |

### 撞擊與手感（遊戲的重點）
- **移動**：手機傾斜 = 加速度（像把一顆彈珠放在手機上）。傾得越多加速越快，有慣性、會滑，轉彎要提早，這種「不好控制」正是樂趣。
- **撞擊**：兩顆陀螺碰到時，雙方各自被彈開；**撞擊時速度越快的一方，把對方撞得越遠、自己被彈得越少**（用相對速度與質量算，不是純彈性碰撞）。
- **衝撞**（右下角按鈕）：按一下往目前移動方向猛衝一小段，有冷卻（約 2 秒）。衝撞中的撞擊力量加倍，但撞偏會衝出平台（高風險高報酬）。
- **轉速（耐力）**：每顆陀螺有轉速條，會緩慢下降，撞擊與衝撞會額外消耗。轉速越低 → 移動越飄、撞擊越弱、畫面上陀螺開始搖晃；歸零 → 停轉淘汰（和掉出平台一樣）。這讓「縮在角落不動」也不安全。（待決定：MVP 要不要做；建議 M3 再加）

## 3. 手機操作與陀螺儀（這個遊戲最大的技術風險）
### 控制方式
```
┌─────────────────────┐
│  （上方：回合／存活人數）  │
│                     │
│        ◯            │   中間：傾斜指示（一顆泡泡，顯示目前傾斜方向與力道）
│       ( • )         │
│                     │
│  [校正]       ┌─────┐ │   左下：校正（把現在的握法當作「水平」）
│              │ 衝撞 │ │   右下：衝撞（大按鈕，拇指好按）
│              └─────┘ │
└─────────────────────┘
```
- 傾斜 → 取手機的 `deviceorientation`（`beta` 前後傾、`gamma` 左右傾），減掉「校正」時記下的角度，除以 30° 得到 -1～1 的方向向量；±3° 內當作沒傾斜（死區），再做一點平滑（避免感測器抖動）。
- 手機旋轉成橫向時，依 `screen.orientation.angle` 把 x、y 對調／反向。建議直接把控制畫面鎖定直向。
- 準備流程：**所有人先按「準備好」**（這一下同時完成 iOS 的感測器權限、校正），主畫面顯示誰準備好了，全部準備好或 20 秒後才開打；沒按的人自動改用搖桿（見下）。

### 必須知道的限制（需實機驗證）
1. **感測器只有在 HTTPS 才能用**：Render 網址（`https://…onrender.com`）可以；**區網 `http://192.168.x.x` 不行**（手機瀏覽器會把陀螺儀擋掉）。所以開發測試要嘛直接用 Render，要嘛用 https 隧道（例如 cloudflared / ngrok）。
2. **iPhone 需要使用者授權**：`DeviceOrientationEvent.requestPermission()` 必須在「點擊」事件裡呼叫，所以一定要有那顆「準備好」按鈕；被拒絕後要到 Safari 設定才能重開，畫面要提示怎麼辦。
3. **不是每支手機都有可靠的陀螺儀**（舊機、省電模式、部分瀏覽器內建的 App 瀏覽器，例如 LINE 內建瀏覽器）。**備案：搖桿模式**，沿用足球的浮動搖桿，輸出同樣的方向向量。主畫面不需要知道玩家用哪一種。
4. 分頁切到背景、螢幕關掉，感測器就停了；沿用足球的「逾時視為放開」保險。
5. 傾斜遊戲比較耗電，已經有 Wake Lock 維持螢幕不暗。

### 網路協定：**不用改 server**
直接重用足球的 `input` 事件：`{ mx, my, dash }` —— `mx, my` 就是傾斜向量（-1～1），`dash` = 衝撞。感測器大約 60Hz，**降到 30Hz** 再送（比足球的搖桿高一點，因為傾斜是連續動作）；有輸入時定期保活，host 超過 0.6 秒沒收到就當作回正。

## 4. 物理（全部在 host 端算，固定 60Hz）
- 每顆陀螺：圓形、半徑 ~26、質量 m、速度 v。輸入向量 → 加速度（約 900 px/s²），再乘一個很小的摩擦（滑行感）。最大速度有上限。
- **陀螺之間的碰撞**：沿連線方向做衝量：`J = (1 + e) · (v_rel · n) / (1/m1 + 1/m2)`，e 取 0.9（很彈）；再依「撞擊方的速度」加上額外的「擊退加成」，並記下 `lastHitBy`（擊殺歸屬）。
- **平台邊緣**：中心離平台中心距離 > 平台半徑 → 開始掉落（`falling`，0.6 秒縮小 + 旋轉後淘汰）；掉落中不能再被推回來（簡單、不會有爭議）。
- **縮圈**：平台半徑隨時間線性縮小（`ARENA_SHRINK_START`、`ARENA_MIN_RATIO`）。
- 10 人同場的運算量和足球 10 人同等級（圓形碰撞、O(n²) 才 45 對），效能沒有問題。

## 5. 角色呈現
- **玩家的大頭 = 陀螺的上蓋**：`head` 圖貼在一個會旋轉的圓盤中央，圓盤外圈是玩家選的**衣服顏色**（顏色本來就每人唯一，剛好用來辨識）；圓盤下面有陰影，撞擊時有火花與「碰！」字，畫面輕微震動（hit-stop 幾格增加打擊感）。
- 轉速越高旋轉越快（頭圖看起來糊成一圈的樣子可以用快速旋轉 + 殘影表現）；轉速低時畫面上歪歪倒倒。
- 掉出平台：縮小、旋轉、淡出，並在落水處濺水花。
- **不需要新美術**：用現有的 `head` 圖與顏色；平台與背景用程式畫（可選：之後你可以提供平台貼圖）。

## 8. 風險與對策
| 風險 | 對策 |
|---|---|
| 區網 http 用不了陀螺儀 | 一律在 Render（https）測；本機開發用 https 隧道或搖桿備案 |
| iPhone 授權被拒 / App 內建瀏覽器沒有感測器 | 準備流程偵測，失敗自動切搖桿模式並提示「用 Safari / Chrome 開啟」 |
| 傾斜太靈敏或太遲鈍，每個人手感不同 | 靈敏度做成常數（`TILT_FULL_DEG`），並提供「校正」；之後可以在手機端加一個靈敏度滑桿 |
| 感測器雜訊讓陀螺一直抖 | 死區 + 低通濾波；host 端的速度也有阻尼 |
| 網路延遲讓控制「黏黏的」 | 陀螺有慣性與質量，輸入延遲 100ms 以內玩家感覺不出來；不做預測 |
| 被撞出去的爭議（誰撞的、有沒有撞到） | 撞擊與落水全部由 host 判定；`lastHitBy` 3 秒內有效 |
| 一直躲在邊緣不打 | 縮圈 + 轉速下降 |
| 玩家握法不同（躺著玩？） | 準備時的「校正」把當下姿勢當水平，躺著也能用 |

## 附錄：S1 實作細節
- **傾斜怎麼算**：`beta`（上緣壓下去 → 往螢幕上方滾）、`gamma`（右緣壓下去 → 往右滾）的角度，減掉「校正」當下的角度，除以滿傾斜角 `TILT_FULL_DEG`（25°），死區 `TILT_DEAD`（0.1），再做平滑 `GYRO_SMOOTH`。螢幕轉成橫放時依 `screen.orientation.angle` 換算（**橫放的正負號需實機驗證**）。
- **準備階段**：每個人按「準備好」，同一下點擊完成 iOS 授權與校正；全部（在線的）準備好就開始，最久等 `PREPARE_MS`（25 秒），沒按的人當作搖桿。授權過的手機之後「再來一場」不用再按。
- **備案**：不是 https、瀏覽器不支援、iPhone 拒絕授權、1.5 秒內收不到任何感測器資料 → 自動改用搖桿，並在畫面上說明原因。傾斜畫面上也有「改用搖桿」按鈕。
- **碗的調整**（用離線模擬，和 `spinner.js` 同一套物理）：
  - 舊的平面（S0）：8 個追擊 AI、90 秒約 50 次擊殺（太亂）。
  - 只加碗、不改別的：要嘛自己還是衝得出去（亂走的假人 40 秒約 44 次自己掉），要嘛連撞都撞不出去（擊殺 < 5）——因為「自己衝」和「被撞」的能量差不多。
  - 解法：**把自己的推力調小（`ACCEL` 1000、`MAX_SPEED` 380），碗的邊緣拉力調得比推力大（`BOWL_G` 1400）**，自己衝不出邊緣；被撞飛的速度另外允許到 800（`HARD_MAX_SPEED`）並加成（`HIT_BOOST` 1.45），所以還是能被撞出去。結果：亂走假人 40 秒自己掉 ≈ 0.1 次，8 個追擊 AI 90 秒約 21 次擊殺、自己掉 0 次。真人手感要實機再調。
- **網路**：不用新事件；`input` 多帶 `ready`（準備好）與 `mode`（`gyro` / `stick`），server 一併過濾。


## S3 衝撞（已完成）

- 手機：搖桿模式在右側「衝撞」鈕；傾斜模式在傾斜圈下方有「衝撞」鈕。按下瞬間觸發一次，手機端冷卻中按鈕變灰。
- host：往目前操控方向（沒推就往滑行方向；完全沒在動則不觸發、不吃冷卻）加 `RAM_SPEED=520`，持續 `RAM_SECONDS=0.4` 秒；冷卻 `RAM_COOLDOWN=2` 秒；復活無敵中不能衝撞。
- 衝撞中撞到人：對方受到的撞擊力道 ×`RAM_POWER=1.7`（自己不變），速度上限 950。
- 畫面：橘色光圈、起步煙塵、撞擊火花更大。
- 尚未做：轉速（耐力）——是否要做待決定。

## S4 場中障礙（已實作：加速帶、冰面、泥地、彈跳柱、轉盤、旋轉棒、洞；傳送門未做）

目標：讓平台不只是一個圓碗，位置、時機、角色數值（重量、抓地）都影響怎麼打。所有障礙都是「圓盤進到某個區域就套用一個力」或「會動的碰撞物」，物理仍然是 `stepPhysics` 裡的固定步長，不需要手機端改動。

### 障礙種類

| 障礙 | 行為 | 數值（建議） | 風險／變化 |
|---|---|---|---|
| ⚡ 加速帶 | 一塊帶箭頭的長條，圓盤壓過去就沿箭頭方向加速 | 進入時 +450 速度（每盤每 0.6 秒最多觸發一次）；長 140 × 寬 50 | 箭頭指向外圍＝送人出場；指向中心＝幫人回防。加速後速度上限用 `RAM_MAX_SPEED` |
| 🔄 旋轉板（轉盤） | 圓形區域像轉盤，圓盤站在上面會被帶著繞圈（切線方向的力），越靠邊越強 | 半徑 90、角速度 ±1.4 rad/s、切線加速度 700；每回合隨機順／逆時針 | 被甩出轉盤時速度帶有切線分量，常常直接飛出平台；重的（`mass`）比較不容易被甩 |
| 🪵 旋轉棒 | 平台中央一根會轉的實心長棒，碰到圓盤就把它掃開 | 長 220、粗 16、角速度 1.1 rad/s；碰撞時用棒上那一點的線速度當作撞擊速度 | 站在中心很危險；可以反過來把對手誘到棒子前面。第 2 回合縮圈到棒子外就拿掉 |
| 🔴 彈跳柱 | 固定的圓柱，撞到會被強力彈開（像彈珠台） | 半徑 24、彈性 1.3；3~4 根對稱放在半徑 ~130 | 輕的角色被彈得遠，重的比較穩；撞擊力道（`power`）不影響 |
| 🧊 冰面／🟤 泥地 | 區域內抓地（`DAMP`）變小／變大 | 冰：×0.25；泥：×3 | 冰上控制不了、一撞就滑很遠；泥地很難動但不容易被撞飛，給坦克型角色用 |
| 🌀 傳送門（進階） | 成對的圓圈，進去從另一個出來，速度保留 | 半徑 28、冷卻 1.5 秒 | 可以偷襲、也可能自己傳到別人旁邊 |
| 🕳 洞（進階） | 圓盤中心進入就掉下去（和掉出平台同一套 `startFall`） | 半徑 26；放在平台外圍 | 計入「最後撞到我的人」擊殺 |

### 出現與消失（動態障礙）

障礙**不是一開始就擺好**，而是比賽進行到一半隨機出現、各自存在一段時間後消失：

- **時間軸**：出現前 1.5 秒先在地上畫閃爍的虛線輪廓＋音效（預告，這段時間沒有效果、圓盤可以先離開）→ **生效 10 秒** → 最後 1.5 秒閃爍預告消失 → 淡出。整個生命週期約 13 秒，其中真正有效果的是 10 秒。
- **生成節奏**：比賽開始後約 5 秒第一個；之後每 5~8 秒（隨機）生成一個。同時最多 3 個（10 人以上最多 2 個，避免太擠）。
- **位置**：在目前平台半徑 × 0.75 以內隨機挑；離任何圓盤至少 70 px、離其他障礙至少 120 px（挑 N 次選最遠的，沿用 `pickSpawn` 的做法）；第 2 回合縮圈時，圈外的障礙直接提前消失。
- **種類**：從種類池抽（不連續兩個一樣）。第 1 回合池：加速帶、冰面、泥地、彈跳柱、轉盤；第 2 回合再加旋轉棒、洞（更刺激）。
- **方向**：加速帶、轉盤的箭頭／轉向每次隨機。
- **回合邊界**：回合結束時全部清掉；第 2 回合開打倒數時不生成。
- **提示**：主畫面上方飄一行字（例如「⚡ 加速帶出現！」）；手機不用改。
- **AI**：用 `_state()` 看得到目前所有障礙（含剩餘時間），預告期間不理，生效後依規則利用或避開；簡單難度完全無視。
- **資料結構**：`obstacles = [{ type, x, y, angle, spawnAt, activeAt, endAt }]`，物理與畫面都只看 `Date.now()` 和這三個時間點；測試用 `_set()` 可以直接塞障礙進去。

### 實作順序（建議）

1. **S4-1 加速帶 + 冰面／泥地**（純區域效果，最容易、馬上看得出差別）：`zones` 清單、`stepPhysics` 套用、場景畫貼圖（箭頭條紋用預渲染貼圖，不要每格畫）。
2. **S4-2 彈跳柱 + 旋轉棒**（會碰撞的物件）：圓—圓、圓—線段碰撞，棒子用圓盤相對棒面速度算撞擊。
3. **S4-3 轉盤**：區域 + 切線力。
4. **S4-4 動態出現／消失的排程（生成節奏、預告、10 秒生效、縮圈處理）**、AI 配合、音效（加速帶「咻」、彈跳柱「叮」、傳送門）。
5. 進階：傳送門、洞。

### 需要先決定

1. 生成節奏（5~8 秒一個、同時最多 3 個）、預告 1.5 秒是否合適？
2. 想先做哪些？建議先做 S4-1（加速帶 + 冰面／泥地）和彈跳柱，因為不需要新的碰撞形狀。
3. 障礙要不要對衝撞中的圓盤也生效（例如衝撞過加速帶是否更快）？建議生效，但速度上限仍受 `RAM_MAX_SPEED` 限制。
